# 脱口英语 · iPhone App 网页版 v0.4

读英文，学英语。不是翻译器：翻译只是入口，记住、会用、能说才是这个产品。

和 Chrome 扩展共用一套生词本逻辑：扩展里划词存的词，可以导到这里复习、跟读；这里的生词本也可以导回扩展。

## 有什么功能（v0.1）

- **生词本**：手动加词（英文 + 中文 + 来源）；每个词记“认识几次 / 不认识几次”；点 🔊 听读音；点 🎙️ 直接去跟读这个词；可删除。
- **每日复习**：每天抽 10 个词（先抽最不熟的），卡片式：英文在上，点一下翻出中文，点“认识 / 不认识”记数；复习完显示今日完成数，顶栏也一直显示今天已复习几个。
- **跟读**：选一个词，点“听原音”用系统语音朗读；点“开始录音”录下自己的跟读，点“停止录音”后直接在本机回放对比。不上传、不打分。
- **导入 / 导出 JSON**：从 Chrome 扩展导出的 JSON 文件可以导进来（重名的词自动跳过）；也可以把生词本导成 JSON，带到扩展或别的设备。
- **PWA**：可以添加到 iPhone 主屏幕，像 App 一样打开；应用外壳有简单离线缓存。

## 在 iPhone 上怎么用

1. 在 Safari 里打开这个网页版的地址（部署后会给你一个网址）。
2. 点底部的“分享”按钮（方框带向上箭头）。
3. 往下划，点“添加到主屏幕”。
4. 主屏幕上出现“脱口英语”图标，点开就能用，和 App 一样全屏。

注意两点：

- **数据只存在这台手机上**（localStorage）。换手机、清 Safari 数据，生词本就没了，所以要经常点“导出 JSON”备份。
- **录音要在 https 网址上才能用**。部署到 Workers 上就是 https，没问题；在自己电脑上用 `http://localhost` 测试也可以；但用 `http://IP地址` 打开时录音会被浏览器禁掉。

## 以后怎么部署到他自己的 Workers 上

不用改代码，直接把这个目录当静态站发上去。已有的部署路子（`~/workspace/custom-connectors/custom.cloudflare/bin/deploy_workers.py` + surrogate 凭证）就能用，有两种摆法：

1. **单独一个 Worker**：新建一个 Workers 静态站，目录指向 `~/workspace/tuokou-yingyu/webapp/`，得到一个 `https://xxx.workers.dev` 地址，分享给读者打开。
2. **挂在 Bestshopping 主站下面**：把这几个文件放到主站目录的一个子路径（例如 `/tuokou-yingyu/`），一次部署一起上，读者从主站就能点进去。

注意：`sw.js` 的缓存只针对这几个文件，改了 `app.js`/`style.css` 之后要换缓存名（`tuokou-yingyu-v1` 改成 `v2`），不然旧手机可能一直用旧版。如果缓存捣乱，直接删掉 `sw.js` 也行（`index.html` 里注册失败也不影响使用）。

## 文件清单

- `index.html` — 页面结构，四个 Tab：生词本 / 复习 / 跟读 / 对话
- `app.js` — 全部逻辑（localStorage、复习抽词、语音朗读、录音回放、导入导出）
- `style.css` — 手机优先样式，大按钮、大字、底部 Tab
- `manifest.json` — PWA 清单（名字、颜色、图标）
- `sw.js` — 简单离线缓存（应用外壳）
- `icon-192.png` / `icon-512.png` — 主屏幕图标（深蓝底 + 金色“脱”字）
- `README.md` — 本文件

## v0.1 没做的事

- 没有账号、没有云同步：换设备靠 JSON 文件导入导出。
- 没有 AI 打分：跟读和对话只录音回放，不评好坏。v0.2 也没做——iPhone Safari 没有语音识别接口，这是系统限制；桌面 Chrome 有语音识别，以后可以在电脑上做实时转文字。
- 例句 v0.2 已做（见上）。词根、自动翻译还没做：加词要自己填中文意思；扩展做好后，划词存词时自动带上翻译和来源。
- 没有每日提醒：iPhone 的网页版发不了推送，提醒靠读者自己打开；包成原生 App 后再加。

## v0.2 新增（口语）

Haze 最注重口语。词 → 句 → 对话，是这版的学习梯子。

### 词入句

- 生词本里每个词下面点“📝 例句”，最多显示 3 条英文例句（带中文翻译）。
- 例句来源：优先调免费的 Free Dictionary API（免 key）。有的词它没有例句（比如 resilient、serendipity 实测就没有），就显示“这个词暂无例句，你自己造一句吧”，下面有个输入框，自己写一句英文（中文翻译可选填）存下来；自己写的例句可以删除。
- 中文翻译走 MyMemory 免费接口。注意：MyMemory 的免费额度是按 IP 共用的，在云机器上实测已用完（429），在家用网络上一般能通；取不到时只显示英文，并写明“翻译暂时没取到”，不会把警告文本当翻译存进去。
- 每条例句都能点 🔊 朗读、点 ● 录音跟读一遍，回放对比。例句取到一次就存在生词本里，下次打开不用再联网。
- 导出/导入 JSON 时例句一起带走。

### 情景对话

- 底部 Tab 加了第四个“对话”。3 个情景，各 8 句话：① 咖啡店点单 ② 问路 ③ 自我介绍。
- 玩法：对方的话 App 会自动朗读（英文+中文都显示）；轮到你时显示一句建议回答，先听一遍，再点“录下你说的”录下来自己听，点“下一句”继续；练完显示完成。
- 诚实说明：**iPhone 的 Safari 没有语音识别接口**，做不了实时听写、打不了分，这里不打分——录音只录给自己听，对比着练。想让对话变成 AI 自由接话，得等以后接自定义接口（见下面的设置）。

### 设置

- 顶栏右上角 ⚙️：可以填自定义 OpenAI 兼容接口地址 + Key，只存在这台手机的浏览器里（localStorage），不上传。
- v0.2 先不用它回话（对话是固定剧本），只是先把接口留着：以后对话想让 AI 自由接话时再用。

### v0.2 之后还没做的事

- 没有实时打分：iPhone Safari 没有语音识别接口，这是系统限制，不是没做；桌面 Chrome 有语音识别，以后可以在电脑上做实时转文字。
- 没有云同步：换设备还是靠 JSON 导入导出。
- 录音还是要 https：部署到 Workers 上就是 https；国内那份 VM 地址是 http，录音会被禁——想练跟读和对话录音，走 Workers 的 https 链接。
- 缓存名已升到 `tuokou-yingyu-v3`（v0.3 改了 app.js/style.css/index.html），旧手机第一次打开会自动换新版。

## v0.3 新增（成就感反馈）

Haze 在 iPhone 上打开后提的要求：点东西的时候要有反馈，让人有成就感——烟花、动画、震动都行。

### 烟花 + 鼓励语

- 手写 canvas 彩带烟花（90 个粒子，金、深蓝、绿、红、橙五色，带重力、旋转和淡出），不引任何外部库，离线也能用。动画约 1.8 秒自己收，不挡操作。
- 触发点只放在真正值得庆祝的时刻，不会每点一下都放：① 完成一组每日复习 ② 完成一个情景对话 ③ 当天第一次存词（一天只庆祝一次存词）。
- 每次烟花配一句随机鼓励语（8 句轮换，不会连续两句重复），比如“又拿下一个！”“这句你会说了！”“开口就是赢！”

### 点按反馈

- 所有主要按钮加了按下效果：点下去立刻轻微缩小 + 颜色变深（`.btn`、底部 Tab、设置按钮、情景卡片、复习卡片都有），0.08 秒的过渡，手感上点下去就有反应。

### 震动

- 完成时调一次 `navigator.vibrate(60)` 短震，但先判断支不支持再调，不支持就跳过。
- **诚实说明：iPhone 的 Safari 不支持网页震动**（`navigator.vibrate` 这个接口在 iOS Safari 上根本没有），这是系统限制，所以 iPhone 上完成时只有烟花 + 声音，没有震动；安卓 Chrome 上震动能用，会短震一下。不要以为 iPhone 没震就是坏了。

### 成功音

- 用 WebAudio 现场合成一声短促的“叮”（880Hz + 1320Hz 泛音，0.6 秒淡出），不用音频文件。
- 设置里加了“音效开/关”，默认开；关了就不响。开关存在本机 localStorage，只影响这台手机。

### v0.3 之后还没做的事

- 烟花只在完成时刻放，不做常驻动画；鼓励语目前是固定 8 句，没接 AI 生成。
- 缓存名已升到 `tuokou-yingyu-v3`（v0.3 改了 app.js/style.css/index.html），旧手机第一次打开会自动换新版。

## v0.4 新增（点按反馈 + 换声音 + 设置面板好关）

Haze 在 iPhone 上真机试了 v0.3，提了两个问题，外加一个设置面板体验问题。

### 每次点按都有明显效果

- v0.3 的 `:active` 按下效果在 iPhone Safari 上基本看不出来（iOS 对 `:active` 支持很弱，0.08 秒、0.97 缩放太轻了）。
- 改成两层：① 点按涟漪——手指点下去的地方扩开一个金色圆圈（深色按钮上是白色圆圈），约 0.35 秒，覆盖所有按钮、底部 Tab、情景卡片、复习卡片；② 按下状态加重——缩放 0.94、颜色明显变深、过渡 0.12 秒。`:active` 还留着当兜底。
- 烟花还是只留给完成时刻（完成一组复习、完成一个情景对话、当天第一次存词），不会每点一下都放。

### 朗读声音：自己挑 + 一次读完

- 设置里加了“朗读声音”选择器，列出这台手机上所有的英文语音（名字 + 语言），选好就记住，下次打开还是这个声音；旁边有“试听”按钮，点一下就用这个声音读一句给你听。
- 默认挑最好的：优先含 Enhanced / Natural / Google US English / Samantha / Alex 的英文语音。
- 流畅度：每句话/每个词只建一个朗读任务，一次读完，不拆段；读之前先取消排队里没读完的旧内容（再等 80 毫秒才读，iOS 上取消后立刻读有时会被吞掉）；语速 0.95、音调 1.0。
- 之前难听、不连贯的原因：一是 iPhone 默认的那个英文女声本身就是这个水平，二是几段朗读叠在队列里、听着断断续续。现在两个都改了。

### 微软 Edge 在线好声音：实测调不通，没硬上

- 想法是接微软 Edge 免费的在线神经网络声音（比本机声音好得多），从网页里直接调。
- 实测结果：声音列表接口是通的（200，返回了全部声音），但合成用的 WebSocket 握手被微软拒绝（403），三个来源都试了（Workers 域名、Edge 插件来源、不带来源），全是 403。
- 原因查清楚了：微软现在给这个接口加了验证（Sec-MS-GEC v2 令牌，要用一套自定义的哈希算法 + 时钟校准来算，版本号还跟着 Edge 的版本走），握手还要带 Edge 插件的来源——浏览器页面发不出这个来源，自己的来源又不被接受。把这套验证搬到网页里做又大又脆，微软一升级就断，没法当稳定的功能交给读者。
- 所以 v0.4 没接在线声音，只做了上面①②；设置面板里也写明了这一点。

### 设置面板：三种关法

- 以前关掉设置必须再点一次“设置”，很别扭。现在三种都管用：① 点面板外面的空白处就关掉 ② 面板右上角有个明显的 × ③ 手机上从面板顶部往下滑就收起（滑动时面板会跟着手指走一点，滑过 60px 才关，不够就弹回来）。打开还是点右上角的 ⚙️。
- 缓存名已升到 `tuokou-yingyu-v4`（v0.4 改了 app.js/style.css/index.html），旧手机第一次打开会自动换新版。

## v0.5 新增（设置面板真正关得掉 + 打开就有词可学）

Haze 在 iPhone 上真机试了 v0.4，又提了两个问题。注意：两端线上（Workers 和 VM）验过都是 v0.4 的文件，所以问题不在部署，在代码本身。

### 设置面板：两个真原因都修了

- 原因 1：点“保存设置”之后面板根本不关——v0.4 的保存处理只弹一句“设置已保存”，不关面板。v0.5 改成：保存成功后弹一句提示，然后直接关掉面板（地址和 Key 只填了一个、保存失败时不关，等填好再说）。
- 原因 2：点外面关用的是 document `click`——iPhone 的 Safari 在普通空白处点按时不一定会触发 `click` 事件（这是 iOS 的老毛病），所以 v0.4 的“点外面”在他手机上经常没反应。v0.5 改成用 `pointerdown` 来判断点外面（手指一按下去就触发），`click` 留着当兜底；点在面板内和设置按钮上的照样排除，不会误关。
- 加固三件：① CSS 里加了 `[hidden]{display:none!important}`，保证 hidden 属性永远不会被别的 display 规则盖掉；② 右上角 × 按钮保证 44×44px 的可点区域，肉眼可见；③ 设置面板底部加了一行小字“版本 v0.5”，以后他一眼就能看出自己打开的是不是新版，缓存旧版的问题藏不住了。
- 关法现在一共六种，全留着：点外面、点 ×、往下滑、Esc、再点一次 ⚙️、点“保存设置”后自动关。

### 零门槛开局：打开就有词，不用自己填

- 之前的问题：一上来就让用户自己写、自己填才能存词，等于先考勤奋，劝退人。
- 改法：第一次打开（生词本还是空的），自动把“日常开口”那包 10 个词加进生词本，不用打一个字，直接点“复习”就能开始；另外 3 个词包（工作学习 / 出门生活 / 聊天夸人）各一张卡片，点一下整包加入（按单词去重，已有的不重复加）。词包里的词都带中文翻译和例句，加进来就能点“例句”看、能听、能录音。
- 词包数据在 `starter-words.json` 里（4 包 × 10 词），用 fetch 取；取不到就用 app.js 里内嵌的一份“日常开口”10 个词当兜底（内容和文件里那包一样），保证第一次打开一定有词可学。已经有词的老用户不会被重复加——第一次打开自动加只做一次（localStorage 里记了个标记），删了也不会再自动塞回来；想加回来就点词包卡片。
- 手动加词、导入导出都留着，没动。
- 缓存名已升到 `tuokou-yingyu-v5`（v0.5 改了 app.js/style.css/index.html/sw.js），旧手机第一次打开会自动换新版；`starter-words.json` 也进了缓存，离线也能取词包。

## v0.6 新增（自动加词条件放宽 + 缓存换代）

Haze 在真机上试了 v0.5，说设置和填生词量的问题还是没解决。查实了两个原因，各修一个：

### 自动加词：生词本里有词也照样加

- 原因：v0.5 的自动加词只在生词本完全是空的时候才触发（`words.length === 0`）。Haze 之前测试时已经往生词本里手动加过词，所以他的生词本不是空的，10 个日常词永远不会自动出现。**这是设计问题，不是他操作错了**——手动加过词的老用户反而被挡在门外。
- 改法：条件改成“只要还没加过日常包就加”，不管生词本里已经有几个词（`starterSeedPending = !starterSeeded()`，`words.length === 0` 那个条件删掉）。去重逻辑不动（按单词去重，已有的不重复加）；加成功才弹提示，加了 0 个不弹；标记还是只做一次，之前已经加过的不会再塞一遍；词包卡片保持原样。
- 注意：之前在 v0.5 里已经自动加过日常包的用户（标记已记下），v0.6 不会再重复加；这次新受益的是“手动加过词、但从来没自动加过日常包”的用户。

### 设置面板：六种关法逐一核对，没缺口就不动

- v0.5 源码里的六种关法都接线了：① 保存成功后关面板 ② 右上角 × ③ 点面板外面（pointerdown 判断，click 兜底）④ 从面板顶部往下滑（滑过 60px）⑤ Esc ⑥ 再点一次 ⚙️。CSS 的 `[hidden]{display:none!important}` 和 × 按钮 44×44 也都在。这次逐一核对过，没有接线缺口，所以**设置代码一行没动**。
- 那为什么 Haze 在真机上还是关不掉？最可能的解释不在代码里：他当时看的国内那份（VM）到 2026-11-14 23:40 还是 v0.4——v0.4 的保存不关面板、点外面用的是 `click`（iOS 上经常没反应），正是他说的两个症状。所以先让他认版本：**设置面板底下的小字写着“版本 v0.6”才是新版**，看到 v0.4/v0.5 就说明打开的是旧代码或旧缓存，把标签页彻底关掉再重新打开。

### 认版本

- 缓存名已升到 `tuokou-yingyu-v6`，设置面板底下的版本小字改成“版本 v0.6 · 脱口英语”。旧缓存不会和新版混着用；打开后先看设置底下的小字，写着 v0.6 就是新版。

## v0.7 新增（旧缓存困住 iPhone 的修法：网络优先 + 自救按钮）

Haze 在 iPhone 上试了 v0.6，说设置和生词本的问题“一点也没变”。查实的原因不在 v0.6 的代码里——v0.6 在服务器和全新浏览器里都是好的，两个问题在真机测试里也全通过了。真正的原因是**他手机上的旧版 service worker 缓存赖着不走**：v0.6 之前 sw.js 是“先读缓存”，他 iPhone Safari 里一直跑的是 v0.4 旧代码（设置保存不关、点外面不关、生词本没有自动加词、没有词包卡片），服务器发了新版也到不了他手里。v0.7 只修这个问题，不加新功能。

### 改法

- sw.js 改成网络优先（只针对 index.html、app.js、style.css 这三个外壳文件，打开根地址 `/` 也算 index.html）：每次打开先走网络，拿到新版就用新版、顺手更新缓存；只有断网、网络出错时才读缓存。图标、词包、manifest 保持先读缓存，不动。缓存名升到 `tuokou-yingyu-v7`；install/activate 还是清理旧缓存（activate 时删掉所有不是 v7 的缓存）。以后每次发新版，用户下次打开直接拿到新文件，不再被旧 service worker 困住。

### 设置关法加固（六种关法，全部保留并做结实）

- 新增全屏半透明遮罩层：设置打开时，面板以外的所有地方都被遮罩盖住，点遮罩任意处（pointerdown，一按下去就关）就关面板。面板本身 z-index 比遮罩高一层，始终能点到。
- 下滑关法改成 pointer 事件（touch 和鼠标都管用）：面板任意位置起手，往下滑超过 60px 就关，不再只认顶部 72px 手柄区。面板上加了 `touch-action: pan-x`——竖向拖动不交给页面滚动，pointermove 才能一直收到，手势不再被面板内容滚动抢走；横向滑动不受影响。设置打开时想滚页面，拖遮罩露出来的地方（面板以外）就行。
- 故意没用 `setPointerCapture`：一旦捕获，面板里按钮的 click 会落到面板上，×、保存、输入框就全点不动了。所以下滑超过 60px 时直接在 pointermove 里关掉，不等 pointerup；手指抬起来时（面板上或页面任何地方）再收尾一次。
- 其余四种原样保留：× 按钮、Esc、再点一次 ⚙️、保存成功后自动关。文档级的点外面关（pointerdown + click 兜底）也留着当后备。
